# RC-0.3.9 추천 점수 고도화 가이드

## 목적

RC-0.3.9는 단가표 미매칭 후보의 추천 정확도를 높인다. 추천은 대표의 판단을 돕는 내부 정보이며, 추천 점수나 규칙 변경만으로 Master Data 가격을 변경하지 않는다.

## 점수 계산 기준

| 기준 | 가중치 |
| --- | ---: |
| 품목명 유사도 | 30% |
| 공정/분류 유사도 | 20% |
| 단위 유사도 | 15% |
| 규격/브랜드 유사도 | 15% |
| 공급처 가중치 | 10% |
| 승인/반려 이력 | 5% |
| 가격 차이율 | 5% |

추천 상세에는 품목명, 분류, 단위, 규격, 공급처, 이력, 가격 점수와 최종 점수 및 추천 사유가 함께 표시된다.

## 정규화 기준

- 품목명: 영문/한글 동의어를 공통 품목명으로 변환하고 구분 문자를 제거한다.
- 단위: `㎡`, `m2`, `sqm`은 `M2`, `개`, `pcs`는 `EA`처럼 통합한다.
- 규격: `300 × 600 mm`, `300*600mm` 같은 표기를 `300x600mm`로 통합한다.
- 브랜드/재질/모델: 품목명과 규격에서 식별 요소를 분리해 후보 설명에 제공한다.
- 규칙 센터: 공급처 alias, 품목 동의어, 단위 alias, 규격 패턴, 승인/반려 패턴을 활성 또는 비활성으로 관리한다.

## 공급처와 이력

- 동일 공급처의 일치 후보에는 가중치를 부여한다.
- 공급처가 없으면 중립 점수 50을 적용한다.
- 과거 승인 횟수는 제한된 범위에서 가산하고 반려 횟수는 감산한다.
- 공급처 점수만 높고 품목명, 단위 또는 규격 식별력이 낮은 후보는 HIGH로 승격하지 않는다.
- 승인/반려 패턴 규칙의 조정 폭은 제한해 기본 유사도를 뒤집는 과도한 가중치를 방지한다.

## 가격 차이율

- 현재가 대비 10% 이내는 안전 점수 100을 적용한다.
- 차이가 커질수록 단계적으로 감점한다.
- 현재가의 100%를 초과하는 차이는 안전 점수 0으로 처리한다.
- 가격 유사도는 전체 점수의 5%만 사용하며 가격만으로 매칭을 결정하지 않는다.

## 신뢰도

- `HIGH`: 85점 이상
- `MEDIUM`: 65점 이상 85점 미만
- `LOW`: 40점 이상 65점 미만
- `NO_MATCH`: 40점 미만

RC-0.3.8 회귀 기준인 `HIGH 93 / MEDIUM 66 / LOW 54 / NO_MATCH 0`은 그대로 유지한다.

## 운영 순서

1. 단가 미매칭 추천 센터에서 후보와 점수 breakdown을 확인한다.
2. 추천 점수 규칙 센터에서 공급처, 동의어, 단위, 승인/반려 패턴을 검토한다.
3. 후보를 승인, 반려 또는 보류한다.
4. 승인된 추천만 Price Queue에 연결한다.
5. Queue는 `PENDING_REVIEW` 상태를 유지한다.
6. 실제 단가 보정 워크벤치에서 승인하고 백업을 성공한 뒤 반영한다.
7. 반영 시 old/new price history를 기록한다.

## 안전 원칙

- 추천 규칙 변경만으로 Master Data를 변경하지 않는다.
- 추천 승인만으로 Master Data를 변경하지 않는다.
- Queue 연결만으로 Master Data를 변경하지 않는다.
- 승인, 백업, history 없는 가격 반영을 허용하지 않는다.
- 고객 화면에는 추천 점수, 공급처 가중치, 이력 점수, 후보, Queue, 내부 단가 및 개인정보를 노출하지 않는다.

## 안정화 확인

- 동일 정규화 문자열은 유사도 100점으로 계산한다.
- 공급처만 일치하고 품목명, 단위 또는 규격 식별력이 약한 후보는 HIGH로 승격하지 않는다.
- 규칙이 없을 때 추천 점수 규칙 센터는 안전한 빈 상태를 표시한다.
- UI 서비스는 `window.ecorean.bocDb` 브리지를 사용한다.
- RC-0.3.9 안정화 판정은 `MERGE_READY`이다.
