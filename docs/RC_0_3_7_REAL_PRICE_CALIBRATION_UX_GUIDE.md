# RC-0.3.7 실제 단가 보정 UX 가이드

## 목적

RC-0.3.7은 실제 단가 보정 queue를 대표가 더 빠르게 검토하도록 `실제 단가 보정 워크벤치`를 추가한다.

## 기본 흐름

1. 단가표 가져오기 또는 실제 단가 보정 센터에서 queue를 생성한다.
2. 실제 단가 보정 워크벤치에서 상태, 리스크, 대상 유형으로 queue를 필터링한다.
3. 항목별 현재 단가, 제안 단가, 차이율, 증빙 메모를 확인한다.
4. 대표가 승인, 반려, 보류 중 하나를 선택한다.
5. 승인된 항목만 `백업 후 반영` 버튼으로 마스터 데이터에 반영한다.
6. 반영 후 이력과 backup id를 확인한다.

## 상태 기준

- 승인 대기: 검토 전 상태이며 마스터 단가는 변경되지 않는다.
- 승인 완료: 백업 후 반영 가능한 상태이다.
- 보류: 추가 견적, 업체 확인, 단위 확인이 필요한 상태이다.
- 반려: 이번 단가 반영에서 제외한 상태이다.
- 반영 완료: 백업 후 마스터 데이터에 반영된 상태이다.

## 리스크 기준

- BLOCKING: 차이율이 매우 크거나 보류된 항목이다.
- HIGH: 우선순위가 높거나 차이율이 큰 항목이다.
- MEDIUM: 대표 검토가 필요한 항목이다.
- LOW: 일반 검토 항목이다.

## 안전 원칙

- 승인 전에는 마스터 단가를 변경하지 않는다.
- 승인 후에도 백업 전에는 반영하지 않는다.
- 반려/보류 항목은 반영하지 않는다.
- 고객용 화면에는 queue, 내부 단가, 업체 견적, variance, backup id를 노출하지 않는다.

## 연결 화면

- CEO Dashboard
- 단가 보정 우선순위 센터
- 실제 단가 보정 센터
- 단가표 일괄 가져오기
- 기준 데이터 관리
- Drawer navigation

## 안정화 확인

- `PENDING_REVIEW` 항목은 바로 반영할 수 없다.
- 승인만으로 Master Data 가격은 변경되지 않는다.
- 백업이 성공한 승인 항목만 반영된다.
- 반영 시 old/new 가격과 backup id가 history에 기록된다.
- 승인, 반려, 보류 사유를 queue에 기록할 수 있다.
- RC-0.3.7 안정화 판정은 `MERGE_READY`이다.
