# Conditional Process Trigger Rules

## Purpose

ECOREAN 자동견적 OS는 공정을 공간명만 보고 자동 생성하지 않는다.

모든 공정은 아래 판단 축을 기준으로 생성, 제외, 확인대기 처리되어야 한다.

- 현장 조건
- 철거 범위
- 기존 상태
- 고객 선택
- 선행공정
- 하자 리스크
- 법규/안전 조건
- Case Library 피드백

## Trigger Types

| triggerType | Meaning | Usage Rule |
|---|---|---|
| AUTO | 항상 필요한 항목에만 제한 | 극히 제한적으로 사용 |
| SELECT | 고객 또는 내부 사용자가 명시적으로 선택 | 옵션, 업그레이드, 선택 공정 |
| QTY | 수량 입력 시 생성 | 면적, 개수, 길이 입력이 있을 때 |
| CONDITIONAL | 조건 충족 시 생성 | 대부분의 실무 공정 |
| NEEDS_CONFIRMATION | 조건 부족으로 보류 | 자동 포함 금지 |

## Required Trigger Fields

Every process DB item must include or inherit:

```json
{
  "triggerType": "CONDITIONAL",
  "triggerConditions": ["NEEDS_RESEARCH"],
  "exclusionConditions": ["NEEDS_RESEARCH"],
  "needsConfirmationWhen": ["NEEDS_RESEARCH"],
  "autoGeneratedReason": "NEEDS_CONFIRMATION",
  "customerExplanation": "NEEDS_CONFIRMATION",
  "internalReasonLog": [],
  "relatedRiskFlags": [],
  "diagnosticWarnings": [],
  "caseLibraryFeedback": {
    "recordTriggerDecision": true,
    "recordExclusionDecision": true,
    "recordActualOutcome": true
  }
}
```

## Conditional-First Processes

The following process families must default to `CONDITIONAL`, not `AUTO`:

- 방수
- 배관 수정
- 전기 증설
- 철거
- 폐기물
- 보강
- 몰딩 교체
- 문틀 교체
- 창호 교체
- 타일 재시공
- 바닥 철거
- 단열
- 결로 보수
- 누수 보수
- 하자 보수
- 추가공사

## Creation Conditions

A process may be generated when at least one verified condition is true:

- customerSelected=true
- quantityProvided=true
- demolitionScopeIncludesProcess=true
- existingConditionDamaged=true
- predecessorRequiresProcess=true
- defectRiskRequiresProcess=true
- codeOrSafetyRequiresProcess=true
- fieldInspectionRecommendsProcess=true
- changeOrderApproved=true

## Exclusion Conditions

A process must be excluded or kept pending when:

- conditionNotMet=true
- dryAreaOnly=true
- noDemolition=true
- existingConditionVerifiedGood=true
- customerDeclinedWithApproval=true
- duplicateProcessAlreadyExists=true
- predecessorNotSelected=true
- insufficientInput=true

## NEEDS_CONFIRMATION Conditions

Use `NEEDS_CONFIRMATION` instead of auto-adding when:

- fieldConditionUnknown=true
- demolitionScopeUnknown=true
- existingLayerConditionUnknown=true
- leakHistoryUnknown=true
- quantityMissing=true
- customerSelectionAmbiguous=true
- predecessorDecisionMissing=true
- highRiskExclusionRequested=true

## Diagnostics

Diagnostics must warn when:

- A high-risk process is excluded without approval
- A successor process exists without required predecessor
- A process has `NEEDS_CONFIRMATION` but estimate is being finalized
- A deleted process still has estimate, schedule, purchase order, or cashflow records
- A wet-area tile process exists without waterproof decision
- Plumbing changes exist without waterproof review
- Demolition exists without waste/logistics review
- Change order work exists without approval/payment condition

## Deletion Rule

If a process is removed, all generated dependent records must also be removed or invalidated:

- Estimate line
- Internal cost line
- Schedule task
- Purchase order line
- Labor allocation
- Cashflow line
- Inspection checklist
- Risk node
- Output document line

The deletion decision must be written to ApprovalLog and Case Library when it affects price, schedule, payment, or risk.
