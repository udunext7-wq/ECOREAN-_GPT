# RC-0.3.2 실제 프로젝트 접수 가이드

## 목적

RC-0.3.2 실제 프로젝트 접수는 실제 고객/현장 정보를 견적으로 넘기기 전에 필요한 항목만 정리하고, LightBIM 도면과 단가 준비 상태, 고객 출력 안전성을 순서대로 확인하는 운영 흐름입니다.

## 실제 고객/현장 정보 입력 순서

1. `실제 프로젝트 접수`를 엽니다.
2. 고객명 또는 테스트 고객명을 입력합니다.
3. 현장명, 주소 요약, 건물 유형, 층수, 엘리베이터/주차 여부를 입력합니다.
4. 공사 유형을 `BATHROOM`, `KITCHEN`, `FULL_REMODELING` 중 선택합니다.
5. 면적, 공간 구성, 공사 범위를 입력합니다.
6. 예산 금액 또는 예산 등급을 입력합니다.
7. 희망 시작일/종료일을 입력합니다.
8. `접수 정보 검증`을 실행합니다.

## 개인정보 최소 입력 원칙

- 전화번호, 이메일, 상세주소는 필수 입력이 아닙니다.
- 테스트 중에는 익명 고객명 또는 테스트 고객명을 사용합니다.
- 고객용 출력 payload에는 내부 원가, 마진, PCE, 업체/노무/발주/입고/보정/백업 경로가 포함되면 안 됩니다.
- 접수 로그에는 전화번호, 이메일, 상세주소, 메모가 저장될 때 redaction 처리됩니다.

## LightBIM 연결 방법

1. `LightBIM 도면 가져오기`에서 JSON을 가져옵니다.
2. 생성된 importId를 접수 화면의 `LightBIM importId`에 입력합니다.
3. `LightBIM 연결`을 실행합니다.
4. 프로젝트명, 공간 수, 총 면적, 추천 견적 유형, 수량 경고 수를 확인합니다.
5. 사용자가 선택한 견적 유형과 LightBIM 추천 유형이 다르면 경고를 확인하고 직접 판단합니다.

## 단가 준비 상태 확인

`단가 준비 상태 확인`은 다음을 점검합니다.

- 초기 기준 데이터 존재 여부
- 실제 단가 반영 이력
- `NEEDS_UPDATE` 잔여 항목
- 노무/자재/표준 품목 준비 상태

상태는 다음 중 하나로 표시됩니다.

- `단가 준비 완료`
- `일부 단가 확인 필요`
- `단가 보정 필요`

단가 상태가 일부 부족해도 견적은 생성할 수 있지만, 고객 제출 전 반드시 확인해야 합니다.

## 견적 생성 방법

1. 접수 정보를 임시 저장합니다.
2. 접수 정보 검증을 실행합니다.
3. LightBIM이 연결되어 있으면 LightBIM 수량 기반 견적 초안을 사용합니다.
4. LightBIM이 없으면 수동 면적/공사 범위 기반 견적 경로를 사용합니다.
5. 견적 생성 후 PCE 결과와 생성된 견적 ID를 확인합니다.

## 고객용 출력 전 점검

고객용 견적서나 제안서를 열기 전에 `고객 안전성 검사`를 실행합니다.

차단되는 항목:

- internal cost
- margin
- PCE
- vendor data
- labor cost
- purchase data
- receiving data
- actual used quantity
- variance
- calibration
- backup path
- onboarding issue details
- import rows
- manual matching logs
- approval queue
- profit / risk_score

검사 실패 시 S1 이슈가 자동 기록되고 고객 출력은 차단됩니다.

## 이슈 기록 방법

접수 중 발견한 문제는 심각도 기준으로 기록합니다.

- S1: 고객 내부정보 노출, 데이터 손상, PCE 불가, 백업 실패
- S2: LightBIM/견적/출력 핵심 흐름 실패
- S3: UI 혼란, 누락 라벨, 보완 필요
- S4: 문구, 간격, 비차단 경고

## 첫 실제 고객 프로젝트 운영 순서

1. 전체 백업 생성
2. 실제 프로젝트 접수 초안 생성
3. 고객/현장/공사 범위 입력
4. 단가 준비 상태 확인
5. LightBIM 도면 연결
6. 접수 정보 검증
7. 견적 생성
8. PCE 확인
9. 고객 안전성 검사
10. 고객용/내부용 출력 분리 확인
11. 접수 리포트 생성
